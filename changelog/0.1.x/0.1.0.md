# 0.1.0 — 2026-06-13

Initial release. Wraps the Transitland v2 REST API — the open registry aggregating GTFS, GTFS-Realtime, and GBFS feeds from thousands of operators worldwide. Onestop IDs are the identifier spine; place-name geocoding is delegated to `openstreetmap_geocode`.

## Added

- **`transitland_find_operators`** — find operators by name, point/radius, bbox, country/region, or Onestop ID; returns agencies, places served, and published feeds.
- **`transitland_get_operator`** — full operator record by Onestop ID or internal integer ID, including source tags (Wikidata QID, US NTD ID, social handles).
- **`transitland_find_feeds`** — the open-data catalog: fetch URLs, license terms (redistribution/commercial/derived/attribution as yes/no/unknown — never inferred), and last-fetch freshness. Filter by operator, spec, fetch state, or search.
- **`transitland_find_routes`** — routes by point/radius, bbox, operator, Onestop ID, or GTFS mode; route_type mapped to a human-readable mode label.
- **`transitland_find_stops`** — stops/stations by point/radius, bbox, Onestop ID, or operator network, with location type, wheelchair accessibility, and timezone.
- **`transitland_get_departures`** — departures with a per-departure `realtime` flag and `schedule_relationship` (STATIC vs SCHEDULED and mutation states), distinguishing live GTFS-Realtime predictions from static schedule, plus a top-level `realtimeAvailable`.
- **`transitland://operator/{onestop_id}`** and **`transitland://feed/{onestop_id}`** resources mirroring the operator and feed records.
- `TransitlandService` — direct HTTP client (no SDK) with `apikey` query injection, latest-feed-version slicing, and 401/404/429 error classification. The Transitland `meta.next` pagination URL embeds the API key in plaintext; the service discards it and surfaces only the opaque integer `after` cursor, so the key never reaches tool output or logs.
