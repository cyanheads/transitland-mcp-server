# 0.1.1 — 2026-08-21

Framework adoption release — `@cyanheads/mcp-ts-core` ^0.10.6 → ^0.12.3 (the SDK v2 migration) plus dependency refresh and packaging upkeep. No new tools; the wire changes below come from the SDK v2 contracts the server now serves.

## Changed

- **Framework adoption** — `@cyanheads/mcp-ts-core` ^0.10.6 → ^0.12.3: every HTTP endpoint also serves protocol revision 2026-07-28 alongside existing clients; **tool inputs are strict** — an argument key the schema doesn't declare is rejected by name instead of ignored; advertised schemas move to JSON Schema 2020-12 and declare the error envelope in `outputSchema`.
- **Guard error codes** — `no_filter` / `incomplete_point` rejections on the four find tools classify as `ValidationError` (-32007) with the recovery hint carried at `data.recovery.hint`, replacing `InvalidParams` (-32602).
- **404 log noise** — `get_operator` / `get_feed` pass `expectedStatuses: [404]` to `fetchWithTimeout`, so an absent Onestop ID logs at debug instead of error; request contexts derive from the handler `ctx` directly.
- **Bun 1.4.0 images** — both Dockerfile stages move to `oven/bun:1.4.0` with BuildKit install-cache mounts; the build stage installs with `--ignore-scripts`, production omits optional peers (`--omit=peer`), and the amd64/arm64 build runs natively per platform. `packageManager` bun@1.4.0; `engines.bun` stays `>=1.3.0`.
- **Supply-chain guard** — `bunfig.toml` holds freshly published versions for 3 days (`minimumReleaseAge`, framework excluded) and runs the Socket install scanner; `.gitattributes` added (LF normalization, generated-file markers); `.gitignore` anchors `data/` so `src/data/`-style paths stay trackable.
- **`.mcpb` portability** — `clean-mcpb` also strips platform-specific native bindings from bundles; `lint:packaging` verifies both strip classes.
- **Author metadata** — `package.json` and `manifest.json` author fields carry Casey Hand with contact URL.

## Added

- **Test tiers** — smoke (every tool and resource through handler → output parse → `format()`), integration (`transitland_get_operator` contract suite), and fuzz (property-based coverage of all six tools) suites from the framework templates, wired as separate Vitest projects; `test:coverage` script backed by `@vitest/coverage-istanbul`.
