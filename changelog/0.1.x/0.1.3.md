# 0.1.3 — 2026-10-07

## Changed

- **Argument repair and rejection hints** — framework 0.13.9 repairs safe integers sent for string IDs and JSON-stringified objects when the repaired input validates; rejected arguments name field paths and accepted keys.
- **Error responses** — framework 0.13.10 adds request IDs and fills declared recovery hints for matching tool and resource failure reasons; redundant recovery forwards are removed and contract tests cover both tool error surfaces.
- **Client logging** — framework 0.13.11 honors `MCP_LOG_LEVEL` and redacts sensitive fields in log notifications.
- **Error data** — framework 0.13.13 stops adding `data.rootCause` to error responses; cause information remains in server log records.
- **Request correlation** — framework 0.13.12 generates request IDs independently of the client's JSON-RPC ID, which logs retain as `jsonRpcId`.
- **Configuration docs** — document source session defaults, meaningful environment overrides, logging limits, failed-call payloads and signal-specific OTLP endpoints in the README and `.env.example`.
- **Docker** — Bun 1.4.0 → 1.4.2; native build-platform stages cross-install production bindings, install telemetry peers at framework ranges through supply-chain guards, and prune musl-only bindings.
- **Packaging** — exclude built MCPB assets from npm, and caches, logs and development notes from bundles; env files and registry credentials stay outside Docker contexts.
- **Development tooling** — sync framework skills and scripts, including portable TODO/antipattern scans, import-failure checks, packaging validation and tag validation before GitHub releases.
- **CodeQL** — analyze each language separately under its canonical category.
- **Package metadata** — align descriptions across npm, plugins, bundle, citation and Docker surfaces.

## Fixed

- **Registry launch configuration** — npm entries use `npx` without npm-script arguments, and the HTTP entry fixes `MCP_TRANSPORT_TYPE=http`.
